# AI 用例管理平台 产品需求文档（PRD）

| 项 | 内容 |
|---|---|
| 产品名称 | AI 用例管理平台（AI Testcase Studio） |
| 文档版本 | v1.2 |
| 最后更新 | 2026-07-09 |
| 状态 | 已实现（v1 全量功能） |

## 1. 背景与问题

测试团队在传统用例编写流程中面临三个核心问题：

1. **编写效率低**：从 PRD 到可执行用例平均耗时 2~3 天/模块，大量时间花在格式整理与重复劳动上。
2. **覆盖不稳定**：用例覆盖度依赖个人经验，边界与异常场景经常遗漏，且无量化手段衡量。
3. **知识不沉淀**：业务规则、历史缺陷散落在文档与聊天记录中，新人重复踩坑，AI 直接生成又容易脱离业务背景产生幻觉。

本产品将 LLM 引入用例生产流程，同时保留人工评审兜底，形成"AI 生成 + 人工评审 + 知识沉淀 + 效果评测"的闭环。

## 2. 目标用户与场景

| 角色 | 场景 |
|---|---|
| 测试工程师 | 拿到 PRD 后快速生成候选用例，评审后入库，导出到用例管理系统或直接执行 |
| 测试负责人 | 查看生成质量指标（采纳率、覆盖率），评估 AI 引入效果 |
| 新人/外包 | 通过知识库沉淀的业务规则快速理解被测系统 |

## 3. 核心流程

```
需求导入 → FeatureList（功能点确认）→ 用例生成（策略 + 专项 + RAG）→ 评审入库 → 导出 → 复盘沉淀
```

每一步的产物都可回溯：需求文档 → 功能点 → 生成任务 → 候选用例草稿 → 入库用例，全链路保留关联关系。

## 4. 功能需求

### 4.1 项目管理

- 支持项目的创建、编辑、删除、搜索与排序（最近活跃/创建时间/名称）。
- 项目名称必填，1~200 字符；删除项目须二次确认，并级联删除需求、生成任务与知识库数据。
- 首页展示"继续上次工作"入口，根据项目最近状态推荐下一步动作。

### 4.2 需求导入

- 三种导入方式：粘贴文本、上传文件（.docx / .md / .markdown，≤10MB）、导入功能清单（.xlsx / .md）。
- 上传文件不填标题时默认取文件名；.doc 等不支持格式须给出明确引导。
- 导入后调用 LLM 结构化解析为功能点列表（模块 / 功能点 / 描述 / 验收标准 / 约束 / 优先级）。

### 4.3 功能点确认（FeatureList）

- 功能点支持行内编辑、新增、删除；支持全量或部分勾选确认。
- 已确认文档被修改后自动回退为待确认状态，防止生成与确认内容不一致。
- 测试范围卡片：维护「不测范围」与「风险/待澄清」，生成时注入提示词（不测范围跳过、风险优先补测）；支持 AI 生成范围建议。
- 功能清单支持导出 .xlsx / .md，导出文件可再导入还原（往返一致）。

### 4.4 用例生成

- 生成策略：快速冒烟（每功能点约 3 条，全部标记冒烟）、完整覆盖（功能/边界/异常三类）。
- 专项 Skill 可叠加：安全/权限（security）、接口测试（api_test）。
- RAG 开关：开启后按功能点检索项目知识库，将相关业务规则注入提示词，并在任务上记录引用溯源（knowledge_refs）。
- 生成为异步任务，前端轮询展示进度与阶段文案；未确认功能点的文档禁止发起生成。
- 生成完成后自动执行规则质检（过滤空用例、统计覆盖率）与 AI Judge 评分（相关性/可执行性/可验证性 1~5 分 + 幻觉标记）。

### 4.5 评审入库

- 候选用例支持采纳、驳回（必选原因，用于 badcase 归因）、编辑（记录 was_edited 信号）。
- 已驳回用例不可再采纳；支持跨分页一键全选。
- 全部处理完自动进入完成页，展示采纳/驳回/采纳率统计；支持"完成评审（跳过剩余）"。
- 生成记录页可查看历史任务列表与草稿明细。

### 4.6 用例库

- 入库用例按 项目 → 模块 → 功能点 三级目录组织，支持列表与脑图两种视图。
- 脑图支持全屏、缩放；目录支持重命名（级联更新用例归属）。
- 用例支持编辑、删除、按冒烟标记筛选。

### 4.7 知识库（RAG）

- 每个项目独立知识库，支持业务文档 / 历史用例 / 缺陷记录三类来源。
- 入库流程：按 Markdown 标题分块（超长块按句切分）→ 向量化 → 写入 ChromaDB；分块保留标题路径便于溯源。
- 提供检索测试入口验证召回效果；删除文档同步清理向量。

### 4.8 AI 评测

- 评测样本：PRD 原文 + 人工标准测试点（checkpoints）。
- 评测运行：对样本批量执行"生成 + 评分"，产出生成成功率、可用率（评分 ≥4）、场景召回率、重复率、幻觉数、token 消耗等指标。
- 支持运行标签区分不同配置（如换模型、改 Prompt 后回归对比）。
- 结果可下钻到单条用例，查看问题用例与未覆盖测试点。
- 评测数据存放在隐藏项目中，与业务数据完全隔离。

### 4.9 系统设置

- 三套模型独立配置：用例生成模型、评测模型（防自评偏置，留空回退生成模型）、Embedding 模型。
- 内置 13 家厂商预设（DeepSeek、智谱、通义、Kimi、豆包等），选择后自动回填地址与模型。
- API Key 保存后仅显示掩码；支持 Mock 模式（无 Key 时自动降级），保证演示与测试可离线运行。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 结构化解析 ≤30s；单任务生成 ≤5min（10 个功能点内）；页面首屏 ≤2s |
| 可用性 | LLM 调用失败任务标记 failed 并保留错误信息，不阻塞其他功能 |
| 数据安全 | API Key 不明文回显；上传文件大小与类型白名单校验 |
| 可测试性 | 全部 AI 路径提供 mock 实现，支持离线自动化测试 |

## 6. 技术架构概览

- 前端：React 18 + Ant Design v6 + Vite
- 后端：FastAPI + SQLAlchemy + SQLite（开发）
- AI：OpenAI 兼容 Chat/Embeddings API；Skill 插件架构（manifest + handler + prompt）
- 向量库：ChromaDB（嵌入式）
- 自动化测试：pytest + requests（接口）、Playwright + POM（UI）
