## BUG-001 删除项目未级联清理知识文档与向量

- **级别**：S1　**模块**：知识库　**发现方式**：接口自动化首跑（test_list_knowledge_docs / test_rag_generation_records_knowledge_refs）
- **现象**：删除项目 A 后新建项目 B，B 的知识库列表出现 A 的文档；开启 RAG 生成时检索命中 A 的旧向量（表现为引用了「订单业务规则」而非本项目文档）。
- **根因**：`Project` 模型只对 requirements / generation_tasks / testcases 配置了 `cascade="all, delete-orphan"`，`KnowledgeDocument` 没有配置级联；删除项目后知识文档行残留。SQLite 复用被删除的项目主键后，新项目按 `project_id` 查询即命中旧数据；对应的 Chroma collection（按 `project_id` 命名）同样残留旧向量。
- **修复**：`Project` 增加 `knowledge_documents` 关系并配置级联删除；`DELETE /projects/{id}` 删除前逐一调用 `delete_document_vectors` 清理 Chroma 向量。
- **回归**：`autotest/api/test_knowledge.py` 全部用例通过；`test_rag_generation_records_knowledge_refs` 验证引用只来自本项目。

## BUG-002 评测运行汇总成功率恒为 0%

- **级别**：S1　**模块**：AI 评测　**发现方式**：用户查看评测结果时发现
- **现象**：评测运行正常完成，单样本明细指标正常，但运行级汇总指标（成功率/可用率/召回率）全部为 0。
- **根因**：迭代"评测进度可视化"时重构了运行循环，误删了 `sample_metrics.append(metrics)` 一行，导致聚合计算入参恒为空列表。
- **修复**：恢复 append 逻辑；对受影响的历史运行执行指标回填脚本。
- **教训**：聚合类逻辑必须有断言级别的自动化覆盖，重构不能只靠肉眼 diff。


## BUG-005 草稿接口未返回 was_edited

- **级别**：S3　**模块**：评审入库　**发现方式**：接口自动化（test_edit_draft_marks_was_edited 首跑 KeyError）
- **现象**：`GeneratedCaseDraft` 模型已有 `was_edited` 字段且编辑接口会写入，但 `GeneratedCaseDraftOut` schema 未声明该字段，响应中缺失，前端与统计无法感知"编辑后采纳"。
- **根因**：加字段时只改了模型与写入路径，遗漏了输出 schema。
- **修复**：`GeneratedCaseDraftOut` 增加 `was_edited: bool = False`。

## BUG-006 评审表头全选只选中当前页

- **级别**：S3　**模块**：评审入库　**发现方式**：UI 自动化（E2E 采纳后仍停留在评审页）
- **现象**：草稿超过一页时，勾选表头全选后点「采纳选中」，第二页草稿仍是待评审，流程不进入完成页。
- **结论**：Ant Design Table 表头复选框语义即"全选当前页"，产品已提供跨页「一键全选」按钮，判定为符合预期的产品行为，不做代码修改；UI 自动化改用「一键全选」，并在功能用例文档中固化该场景（TC 一键全选跨分页）。

## BUG-007 知识库前端允许 .txt 上传但后端拒绝

- **级别**：S3　**模块**：知识库　**发现方式**：代码走查
- **现象**：知识库上传组件 `accept` 包含 `.txt`，用户可选择 .txt 文件，但后端 `parse_upload` 仅支持 `.docx/.md/.markdown`，上传后才报错。
- **根因**：前后端文件类型白名单不一致。
- **修复建议**：统一白名单——后端 `parse_upload` 支持纯文本 `.txt`（按 markdown 无标题路径分块即可），或前端移除 `.txt`。**当前状态：待修复**。

## BUG-008 评测运行无进度反馈

- **级别**：S3　**模块**：AI 评测　**发现方式**：用户反馈「看不到评测的进展」
- **现象**：评测运行期间页面只有 pending 状态，无法判断是否卡死、跑到哪个样本。
- **根因**：`EvalRun` 只有终态刷新，没有把底层 `GenerationTask` 的细粒度进度向上映射。
- **修复**：后台 watcher 将任务进度映射到 `EvalRun.progress`；两个模型均增加 `stage` 字段输出阶段文案（如「AI 评分（2/4 功能点）」）；前端展示当前样本名与阶段。


## BUG-010 Mock 模式偶发空标题用例

- **级别**：S3　**模块**：用例生成　**发现方式**：手工测试
- **现象**：生成结果中偶发标题为空或步骤为空的无效用例。
- **根因**：LLM 输出解析后缺少最低有效性过滤。
- **修复**：`output_parser` 增加空用例过滤；规则质检统计过滤数量并计入质检报告。
