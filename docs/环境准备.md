# 环境准备与运行指南（macOS / Windows）

拿到本项目代码包后，按本文档从零搭建运行环境。全程约 10 分钟（不含依赖下载时间）。

## 1. 前置软件要求

| 软件 | 版本要求 | 验证命令 | 下载地址 |
|---|---|---|---|
| Python | 3.12+ | macOS：`python3.12 --version`<br>Windows：`python --version` | python.org（Windows 安装时勾选 **Add Python to PATH**） |
| Node.js | 20+ | `node --version` | nodejs.org（LTS 版本即可） |
| npm | 随 Node 安装 | `npm --version` | — |

**无需安装任何数据库服务**：业务数据用 SQLite（Python 自带，首次启动自动建库建表），知识库向量用 ChromaDB 嵌入式模式（随 pip 依赖安装，数据落在本地文件），都不需要单独部署。仅当生产环境要切换 PostgreSQL 时才需要额外装数据库。

> 国内网络建议配置镜像源，否则依赖安装可能超时：
>
> ```bash
> npm config set registry https://registry.npmmirror.com
> # pip 在安装命令后追加：-i https://pypi.tuna.tsinghua.edu.cn/simple
> ```

## 2. 打包/接收注意事项

发送方打包前请剔除以下内容（保护敏感数据 + 减小体积）：

```
backend/data/        # 本地数据库（含 API Key 明文）与向量库
backend/venv/        # Python 虚拟环境
web/node_modules/    # 前端依赖
autotest/venv/       # 测试虚拟环境
autotest/.browsers/  # Playwright 浏览器
.env                 # 本地环境变量（含密钥）
```

如果通过 `git archive` 或克隆仓库分发，以上内容已被 `.gitignore` 排除，无需额外处理。

## 3. 后端搭建

### macOS（终端）

```bash
cd backend
python3.12 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 准备环境变量（回到仓库根目录）
cd ..
cp .env.example .env

# 启动
cd backend
uvicorn app.main:app --reload --port 8000
```

### Windows（PowerShell）

```powershell
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

# 准备环境变量（回到仓库根目录）
cd ..
copy .env.example .env

# 启动
cd backend
uvicorn app.main:app --reload --port 8000
```

> PowerShell 如果提示"禁止运行脚本"导致 activate 失败，先执行：
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

### .env 关键配置

| 变量 | 默认值 | 说明 |
|---|---|---|
| `LLM_API_KEY` | 空 | 留空则自动进入 Mock 模式，无需任何外部服务即可体验全流程 |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI 兼容接口地址 |
| `LLM_MODEL` | `deepseek-v4-flash` | 生成模型 |
| `LLM_MOCK_MODE` | `true` | Mock 开关；配置真实 Key 后改为 `false` |
| `DATABASE_URL` | `sqlite:///./data/app.db` | 默认 SQLite，首次启动自动建库建表 |
| `UNIFIED_AGENT_RUNTIME_ENABLED` | `false` | AI 小助手统一 Runtime 总开关；需同时开启全局与项目 Runtime V2 才生效 |
| `RUNTIME_BUDGET_MODE` | `observe` | `observe` 只记录预算证据，`enforce` 会在下一次受治理调用前执行硬限制 |

> 模型配置也可以启动后在页面「设置」中填写（生成模型 / 评测模型 / Embedding 模型三套独立配置，内置 13 家厂商预设），页面配置保存到数据库并覆盖 `.env`。

验证：浏览器打开 `http://localhost:8000/docs` 能看到 Swagger 文档。

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 生成/解析报「导入失败」 | 多为 LLM 调用失败：检查设置页 Key 是否有效，或先用 Mock 模式验证链路；本机代理工具可能拦截请求（代码已 `trust_env=False` 直连） |
| 端口被占用 | macOS：`lsof -ti tcp:8000 \| xargs kill -9`；Windows：`netstat -ano \| findstr :8000` 找到 PID 后 `taskkill /F /PID <PID>`（前端 5173 同理） |
| PowerShell 无法激活 venv | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 后重开窗口 |
| pip / npm 安装超时 | 换国内镜像源（见第 1 节） |
| 知识库上传后状态失败 | 未配置 Embedding 模型时仅 Mock 模式可用（伪向量）；真实检索需在设置页配置 Embedding API |
| Playwright 浏览器下载慢 | 设置环境变量 `PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright` 后重试 |

## 9. 生成失败候选与保留期

`case_writer` 的结构化输出失败会按失败类型进行有限重试；单个功能点最终失败不会中断其他功能点，任务会标记为“完成但有告警”。可在“评测”页面的“失败候选”标签中补充标准测试点，并提升为可复用的回归评测样本。

失败调用的诊断原文会先脱敏并截断；未被失败候选引用的尝试记录默认保留 90 天。清理通过后端维护入口 `purge_expired_generation_attempts` 显式执行，不会在用户请求路径中自动删除数据。

## 10. 多 Agent 灰度运行

多 Agent 链路采用“LangGraph 外层编排 + Runtime Harness 治理”。`case_writer` 始终先生成基础用例，项目策略与本次任务共同选择的 Specialist 最多并发 2 个；Specialist 失败只记录 warning，不会丢失已经生成的核心草稿。可选 Specialist 及顺序来自 `/skills` Catalog，不在 API 或前端维护固定枚举。

本地启用顺序：

1. 保持 `.env` 中 `LLM_MOCK_MODE=true`，将 `AGENT_RUNTIME_V2_ENABLED=true` 后重启；
2. 确认 `AITC Worker` 窗口持续运行；
3. 在项目“数据概览 → Agent 灰度与效果”中打开项目 Runtime V2；
4. 在同一张卡片中按 Catalog 逐个启用 Specialist 并观察，不要一次性全开；策略保存后会生成新的 Revision，仅影响之后创建的生成任务；
5. 按每个生成任务的最新终态运行去重，累计最近 30 个已结束生成任务后再判断灰度门槛。样本不足 30 个只能作为趋势观察。

报告中的“Specialist 参与采纳”表示该 Agent 出现在已采纳草稿的来源链中，是相关归因，不代表因果提升。历史 BackgroundTasks 没有统一可靠的运行起止时间，因此首版不判断“运行时长不超过基线 1.5 倍”；页面会明确显示基线不可用。

运行详情只展示 Agent、候选数量、耗时、warning 摘要和合并去向，不返回候选原始 payload。重复候选保留审计记录并标记为 `merged_duplicate`；任何 Specialist 结果都不会自动提升为知识。已排队或运行的任务继续使用其已冻结的策略快照，不会读取后来保存的项目策略。

### 10.1 统一 Runtime 与预算灰度

统一 Runtime 把 AI 小助手作为内联父运行，把用例生成/评测作为 Worker 子运行；三者共用 Runtime Harness、取消、事件审计和预算账本。浏览器关闭或 SSE 断线只会中断订阅，不会取消运行；重连会按事件 `sequence` 补读。父回答与已经批准的后台子任务需要分别取消。

建议按以下顺序灰度：

1. 保持 `AGENT_RUNTIME_V2_ENABLED=true`，项目也已开启 Runtime V2；
2. 设置 `UNIFIED_AGENT_RUNTIME_ENABLED=true`、`RUNTIME_BUDGET_MODE=observe` 后重启后端；
3. 通过 `/api/projects/{project_id}/agent-runs/rollout-report` 观察 warning、would-exhaust、interrupted 与历史未知计数；
4. 确认正常运行样本后，再把 `RUNTIME_BUDGET_MODE` 改为 `enforce` 启用硬限制。

`observe` 会记录预算达到 80% 和理论超限事件，但不会拦截调用；`enforce` 会在 LLM、Tool、重试或修复动作发生前原子预留预算，超限时进入“预算已用尽”，已提交的草稿、评测卡和检查点会保留，可创建新运行继续。

## 11. 扩展部署包内 Skill

P0 只发现随当前后端部署包发布的 Skill，不支持在线上传、远程加载或项目级代码覆盖。新增内置 Specialist 时创建：

```text
backend/app/skills/<name>/
├── skill.yaml
├── schemas.py
├── handler.py
└── prompt.md
```

`skill.yaml` 必须声明 `name`、`version`、`title`、`description`、`category`、`stage`、`ui`、`entrypoint`、`input_model`、`output_model`、`execution_order` 和 `timeout_seconds`。可选 Specialist 使用 `category: specialist` 与 `ui.selectable: true`；`execution_order` 决定 Catalog 和执行顺序。`timeout_seconds` 必须在 30～600 秒之间，默认建议 420 秒。

可选 Specialist 还必须声明部署级 Policy：

```yaml
policy:
  max_cases: 5
  default_prompt_version: v1
  prompt_versions:
    v1: prompt.md
```

项目只能启用/禁用 Specialist，或把 timeout、最大用例数收紧到 Manifest 上限以内，并选择已发布的 Prompt 版本；不能在线编辑 Prompt 或提高平台上限。缺少任务快照要求的 Prompt 版本时，系统会明确报错，绝不回退到其他版本。

`entrypoint`、`input_model`、`output_model` 只能使用包内单文件相对引用，例如 `handler:run`、`schemas:PerformanceInput`；不允许引用 `app.services.*` 或外部模块。handler 必须是 `async def run(inputs, context)`，输入和输出必须分别通过 Manifest 指向的 Pydantic 模型，输入模型建议统一 `extra="forbid"`。Mock 模式也必须返回同一输出契约，不能维护另一套结构。

Runtime 只记录 Skill 名、版本、类别、耗时、错误类型和通用脱敏摘要；禁止把输入、Prompt、知识片段、模型原始输出、ValidationError 输入值或 handler 原始异常正文写入运行事件。新增后至少运行 Skill Loader、Mock 契约、全量后端测试和前端 Catalog 测试。

在线安装、项目 Prompt 正文编辑、`SKILL.md` 渐进式资源加载与 Skill 市场属于后续 P2，不在当前范围。

## P1-2b 双轨评测

评测运行会对生成出的测试用例输出两条独立结论：规则轨检查结构完整性、步骤可执行性、预期可验证性、内部一致性、重复度和冻结检查点覆盖；LLM Judge 轨判断业务相关性、场景完整性及边界意识。两条轨道不会合成为一个总分。

每次运行会冻结样本、规则版本和 Judge Prompt 版本，后续编辑只影响新建运行。Judge 调用超时、失败或无法解析时，页面会显示“Judge 不可用（规则结果仍有效）”，不会将该用例直接判为失败。人工金标用例为可选增强输入，没有金标也可以运行评测。

当前双轨输出用于定位质量问题和比较实验结果；基线阈值与发布门禁属于后续 P1-2c，人工反馈沉淀与评测集治理属于 P1-2d。
